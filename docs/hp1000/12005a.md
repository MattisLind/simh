# HP 12005A serial interfaces, test hood and authentic diagnostics

The optional `ASI` device is the VCP interface at SC20 (octal). `ASI1` is an
independent optional interface, default SC21. Both use `hp2100_l_asi.c` and the
shared I/O chip in `hp2100_l_iop.c`. They are disabled by default. Existing
21xx/M/E/F console routing and devices remain selected on those CPU models.

## Reproduce

```
make hp2100
python3 tests/hp1000/run_asi.py
python3 tests/hp1000/run_krnl_disk.py --second-asi
python3 tests/hp1000/run_asic.py --revision 2040
```

All require the supplied original reference files. Results and transcripts are
under `build/hp1000/`. The ASIC command uses a working copy of the diagnostic
disk; the original `24397A.hpi` is never modified.

For an interactive VCP session:

```
set cpu 1000-L
set ASI enabled
set cpu LROM=build/hp1000/12005a/processor-rom.bin
deposit S 400
reset -p
go
```

Switch 0400 selects VCP after the genuine ROM pretest. Original firmware handles
commands: `A000123` followed by return changes A, `%S` single-steps, and `%R`
runs. The simulator interrupt character remains available. The ROM is rebuilt
from the supplied PROM byte lanes without patching HP code.

For the independent card:

```
set ASI1 enabled
set ASI1 loopback
```

`LOOPBACK` wraps serial transmit to receive. `HOOD` instead connects the virtual
24397-60003/60005 diagnostic hood described below. `NOLOOPBACK`/`NOHOOD` remove
them. `SC=<octal>` selects an available address; ASI must remain SC20 to serve
the VCP. Physical priority/enumeration order is ASI, HPI, ASI1. ASI owns the host
keyboard/display; ASI1 does not print its test characters to that console.

## Authentic validation

- Original ROM CPU/memory/I/O pretests and interactive VCP pass. Tests change A,
  execute a single INA, and run into HLT5, checking firmware return and P-SAVE.
- Full original disk KRNL passes with ASI, HPI and ASI1 installed. Completion is
  17770 and LSTATUS177777; all 6,239 original absolute words match their source.
- Authentic ASIC **Rev.2040** passes with the hood: all 15 internal baud settings,
  the external clock test, and `PASS COMPLETE`. Its main program also exercises
  registers, reset, break, data widths, special characters, packed/chained DMA,
  residue, overrun, parity errors and modem signals.
- Seven focused ASI groups pass: programmed I/O, independent-card IRQ/loopback,
  packed DMA/direction changes/special termination, hood clock/reset/modem/parity,
  host-input DMA, final UART-TRE/CINT interrupt distinction, and original VCP.

The unmodified Rev.2040 absolute binary is
`24397-16005_Rev-2040.abin`, SHA256
`39db1ca61b0defd5cc0ec97ada150fe6636958b5af1f510074e6f89e6749a497`.
The runner validates its HP paper-tape checksums and converts its 12,288 original
words to an FMP type-1 memory file, `ASIC40`, appended to a working disk copy.
Every existing file's hash is preserved. The original VCP executes `%BDC27ASIC40`;
no simulator-specific start routine or HP instruction patch is used.

## Older disk ASIC and HP's DDL fix

`run_asic.py --revision 2001` still exercises the original disk's ASIC. It is a
known failing case, not counted as passed: at the 1200-baud iteration, a retained
DDL pending-interrupt indication has no matching pending table entry after the
handler assignment. The old PINT dispatcher executes SFS0,C and takes its
no-entry return without restoring interrupts, leaving the test waiting forever.

The original binaries and HP's supplied DDL sources identify the fix:

| DDL path | Older implementation | Rev.2040 implementation |
| --- | --- | --- |
| No pending entry in PINT | JMP PINT,I, leaving interrupts disabled | JMP PINTX; STF0; JMP PINT,I |

In the original ASIC image, instruction 07620 is `127606` (JMP PINT,I). In the
original Rev.2040 binary, 11672 is `027725` (JMP PINTX); 11725 is `102100`
(STF0), followed by `127660` (JMP PINT,I). These match the no-entry paths in
`24397-18003_Rev-2010.src` and `24397-18003_Rev-2040.src`. The later HP binary
runs to completion on the same emulator. The emulator contains no rule keyed to
these addresses and does not repair or bypass the older program.

## Hood references and modeled signals

The newly supplied **24612-90011**, printed 2-9/2-10 (PDF29/30), Table 2-1 and
Figure 2-1, documents the 24397-60003 Rev.A/Rev.B and 24397-60005 hoods. Combined
with **12005-90001** Table 2-5 and Figure 7-4, this replaces the earlier inferred
wiring. Relevant connections include:

| Jumpers | Function |
| --- | --- |
| T–D | 20mA transmit/receive wrap |
| U–23 | SSD drives the differential receive input, permitting parity-error injection |
| 9–15, 10–17 | Differential SD to secondary receive status |
| W–Z | Unbalanced SD to Data Mode status |
| M–V | Terminal Ready to Receiver Ready |
| B–2, F–3, X–E | Request-to-Send to Incoming Call/Clear-to-Send |
| 6–22, H–21, C–20, L–19 | Modem references drive baud-select lines |
| 5–8 | ECHOM drives baud-generator diagnostic reset |
| K–11 | Special-character select line connects to stop-bit select |
| Hood U1 to pin7 | 1MHz external clock, 16 times serial baud |

`HOOD` selects baud directly from the reference outputs rather than latching it
on ECHO transitions. ECHO's reset pulse holds an active transmission until
release. The external clock corresponds to 62,500 baud. DM and SRD follow serial
output; RR follows TR, and IC/CS follow RS. A receive-line override while parity
is enabled records a functional parity error. Rev.B/60005 optical-link additions
for the 12005B are outside this 12005A model.

## Scope and limits

The shared chip covers configuration triplets/quadruplets, DMA controls, flags,
AUTO/residue/continuation, card parity checks, mode-3 transfers and distributed
masks. Serial DMA covers the diagnostic's packed/word loopback and special
termination paths. CPU, UART and timer timing use functional instruction
lengths in 50ns units, not electrical or microcycle timing.

A diagnostic pass is not complete UART conformance. Start/stop-bit sampling,
per-bit parity/framing faults, every stop-bit-select combination and all host
serial DMA/error cases still need fuller modeling. The current frame model uses
the two-stop-bit configuration used for validation; the hood's K–11 connection
is documented but does not yet provide arbitrary configurable frame formats.
The later optional terminal/optical and extra special-character programs were
not run. Initial zero-count wraparound DMA and full save/restore coverage also
remain open. The original 24397-90002/90003/90005 manuals remain unavailable;
the supplied later interface-diagnostic manual now supplies the hood schematic.
