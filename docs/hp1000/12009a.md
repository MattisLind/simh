# 12009A hardware bring-up

The optional `HPI` device implements a functional subset of the 12009A inside
the existing HP2100 simulator. It uses the shared L-Series I/O chip, the existing
HP-IB bus implementation, and the existing DA Amigo hard-disc endpoint when
selected. It does not alter the RTE master disks or substitute an operating
system for the original firmware.

## Configuration and reproduction

```
make hp2100
python3 tests/hp1000/run_hpi.py
```

The runner requires the privately supplied references and writes results under
`build/hp1000/12009a/tests/`. It reconstructs the original processor ROM from
its byte lanes. Example interactive setup after running the test:

```
set cpu 1000-L
set ASI enabled
set HPI enabled
set cpu LROM=build/hp1000/12009a/tests/processor-rom.bin
attach -r HPI0 hp1000-references/software/diagnostics/archives/24397A.hpi
deposit S 400
reset -p
go
```

At the original VCP, type `%BDC27HPIB` followed by return. This boots the file
named HPIB through the ROM loader and BOOTX, and reaches the original DDL
`READY` prompt. `RU` followed by return starts the diagnostic; enter `27` when
asked for its select code. The current implementation passes the register and
initial packed-DMA checks, but fails in the PHI chip section. This is **not** a
full diagnostic pass. The observed first failure is reported after its line 160
boundary (`ERROR - PHI CHIP/HP-IB CARD FAILURE`).

For the RTE-L master, attach `92070-13401.hpi` instead. `%BDC27` executes its
BOOTX, which reaches HLT 2 at 000204 because SYSTEM is absent. This is a verified
bootstrap checkpoint, not a running RTE-L system.

HPI defaults to fixed select code 27, mask group bit 5, card ID 04027, and one
floppy controller at HP-IB address 0 with two drive units, HPI0/HPI1. Only the
77-cylinder, two-sided, 30-sector, 256-byte raw HPI geometry is supported.
HPI2 is an internal service unit, not an attachable drive.

`SET HPI HARDDISK` connects the card frontend to the existing DA bus and drive
models. Attach drives using DA0..DA3 and DA's existing geometry, byte-order and
bus-address options. `SET HPI FLOPPY` restores the floppy endpoint. Neither
switch is allowed during an active transfer. HPI is disabled by default; its
CPU dispatch and bus callbacks are inactive on pre-L models.

## Hardware references and interpretation

Documented in the supplied **12009-90001 December 1988** manual:

- Table 3-1, printed 3-4..3-6: I/O-chip instructions and flags.
- Printed 3-8..3-11: PHI register-select/read bits, card data/control/status.
- Printed 3-13..3-27: DMA direction, byte packing, chains, completion and residue.
- Table 3-3, printed 3-31: a 7902 status/DSJ DMA example.
- Printed 3-32..3-51: PHI FIFO, interrupts, masks, control and addressing.
  A controller responds to address 30 (decimal), independently of register 7's
  programmed device address; this rule was necessary for authentic ROM startup.
- Printed 4-8: repeated STC transfers and common register-selection data path.

**02103-90005** supplies the distributed mask, Type 3 interrupt and board-ID
rules. **07902-90030 January 1981**, downloaded to the ignored build directory,
confirms the floppy recording geometry. The additionally supplied local
**07902-90060 May 1979** service manual is retained in the reference inventory.
The Amigo command structure follows the existing `hp2100_di_da.c`, the ROM source
`12001-18001`, and the original RTE-L `DD.30` source `92070-18085 Rev.1941`.

The card's write-selected packed-DMA loopback path is inferred from the physical
data path and original diagnostic lines 54..68; it now passes that diagnostic
prefix. It is not a substitute for completing the PHI offline model or checking
all timing and error cases against the schematics.

## Remaining hardware gaps

Offline PHI self-addressing/loopback, CRC, device mode, freeze/secondary-address
handling and all FIFO/interrupt corner cases are incomplete. The external bus
path currently targets controller operation. Timing uses instruction events,
not electrical handshakes. XL/remote DMA mapping, full DMA parity/error handling,
all early-termination cases, and exhaustive CINT/AUTO/DVCMD combinations need
more work. Normal console DMA in the separate 12005A also remains unfinished.

Floppy reads/writes, seeks, identify, status and DSJ cover the bootstrap path;
formatting, defective-track behavior, full-sector commands and complete drive
error/status semantics are not implemented. Passing the bootstrap does not
establish full 7902/9895 conformance. Hard-disc data transfers through this
frontend need broader tests beyond the DA identification exchange.

The separate [RTE-L generation investigation](rte-l-generation.md) tracks media
and generator requirements. Missing SYSTEM media does not block these hardware
checks.

The generated 7902 SYSTEM boot checkpoint and required diagnostic gates are
documented in [rte-l-built.md](rte-l-built.md). The distribution master itself
still has no SYSTEM; the separate generated image now does.

The complete original disk KRNL now passes with ASI SC20 and HPI SC27 installed
(`run_krnl_disk.py`), including shared-chip DMA, parity and multi-card tests.
This supersedes the earlier KRNL I/O-error checkpoint. It does not establish a
full HPIB diagnostic pass; the PHI/controller-specific tests remain outstanding.

## Original HPIB diagnostic completed

`python3 tests/hp1000/run_hpib.py --instructions 30000000` now executes the
unchanged Rev.2001 HPIB from the original read-only `24397A.hpi` through:

- Complete offline PHI/card tests, including FIFO backpressure, delayed/frozen
  DMA, forced reads, secondary addressing, GET, parallel polling and byte DMA.
- Online controller, SRQ and parallel-poll checks.
- IDENTIFY of the 7902 at bus address 0 (`000201` octal).
- Original disc-controller write/read loopback and `PASS COMPLETE`.

Results are in `build/hp1000/hpib-disk/results.json`. The runner distinguishes
interface-only completion from disc loopback; `NO HP-IB DISCS FOUND` is not
accepted as a full pass. The optional two-card interactive test was not run:
only one 12009A is installed. No HP code or original disk bytes were changed.

The frontend now supports the PHI's private offline bus, persistent TA/LA latches,
command parity, high-order-bit access, internal parallel-poll configuration and
FIFO tag decoding. DMA models word prefetch/backpressure and the final N+1
handshake: memory count can roll over while PPOLL holds completion pending.
Card delay/freeze gating uses interrupting conditions, not arbitrary status bits.
PHI polling observes 2us settling and the card's 7us PPDONE interval using the
functional L instruction-time clock. This remains a functional timing model.

The 7902 endpoint now implements controller-buffer loopback at secondary 1Eh,
per 07902-90030 Appendix A (Read/Write Loopback Record). It accesses a separate
256-byte buffer and never writes disk media. IDENTIFY/status/loopback replies
assert EOI on their last byte even when an earlier streaming disk read remains
armed. Disk streaming data retains its prior behavior.

Thirteen grouped `run_hpi.py` regressions pass, including real scratch-image
writes, existing DA identification, offline FIFO/DMA/poll cases, original VCP
pretests and distribution BOOTX behavior. Full three-card KRNL still passes.
The generated RTE-L SYSTEM also still reaches 02003 with all 31,742 words checked.
Earlier incomplete-HPIB statements above are superseded. CRC, comprehensive
peripheral error handling and optional two-card/remote DMA coverage remain open;
passing this diagnostic does not imply complete hardware conformance.

The user supplied ASIC hood wiring from 24612-90011 after this milestone and
requested returning to ASIC before further OS bring-up.
